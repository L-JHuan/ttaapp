# 数据需求

运行 TAP-SID 支持三种输入：工业 JSONL、与 TSMC2014 相同格式的八列 TSV，以及标准事件/POI 两张 CSV 表。

## 1. 工业 JSONL

文件每行是一个 JSON 对象，至少包含：

| 字段 | 含义 |
|---|---|
| `user_id` | 稳定匿名用户 ID |
| `poiid` | 稳定匿名 POI ID |
| `new_key_type` | 层级类别路径 |
| `longitude` | 经度 |
| `latitude` | 纬度 |
| `log_time` | 报活发生时间 |

用户和 POI 可以使用不可逆哈希，但同一实体必须在全部记录中保持一致。程序会把
`new_key_type` 的第一条类别路径映射为 L1/L2，并对同一 POI 的坐标取中位数。
工业输入默认合并每位用户连续上报的相同 POI，稍后再次返回该 POI 时仍保留为新状态。

## 2. TSMC2014 单文件输入

文件不需要表头，每行包含 8 个制表符分隔字段：

| 列 | 含义 |
|---:|---|
| 1 | 匿名用户 ID |
| 2 | POI/Venue ID |
| 3 | 细类别 ID |
| 4 | 细类别名称 |
| 5 | 纬度 |
| 6 | 经度 |
| 7 | 当地时间相对 UTC 的分钟偏移 |
| 8 | UTC 签到时间 |

前三列分别是用户 ID、POI ID 和细类别 ID。原始文件只提供细类别时，程序使用 `configs/foursquare_category_l1_map.json` 将第 4 列映射为粗类别 L1；第 4 列本身作为细类别 L2。当前 taxonomy 在 NYC/TKY 上分别得到 9 个 L1 和 250/247 个 L2。

对于非 Foursquare 类别，数据提供方需要准备一个 JSON 字典，将每个细类别名称映射到粗类别名称，并通过 `TSMC_CATEGORY_L1_MAP` 指定路径。若映射后只有一个 L1，程序会停止并提示修正，避免把无效的单一粗类别用于训练。

同一 POI 出现多个元数据版本时，程序以出现次数最多的类别 ID/名称作为 L2，平局时按类别 ID 和名称排序确定；经纬度使用该 POI 所有签到坐标的中位数。未被 taxonomy 覆盖的细类别归入 `Other`，并记录在 `conversion_report.json`。

## 3. 双表输入（兼容模式）

### 3.1 用户行为表 `events.csv`

一行表示用户访问一次 POI：

| 字段 | 必需 | 含义 |
|---|---:|---|
| `user_id` | 是 | 稳定的匿名用户 ID |
| `poi_id` | 是 | 与 POI 表一致的匿名 POI ID |
| `timestamp` | 是 | 访问发生时间，格式需统一 |
| `timezone_offset_minutes` | 否 | 当地时间相对 UTC 的分钟偏移；整份数据一致时可在配置中统一给出 |

首轮实验只使用一种能够代表真实访问的行为，不混合点击、曝光等不同语义的事件。

### 3.2 POI 元数据表 `pois.csv`

| 字段 | 必需 | 含义 |
|---|---:|---|
| `poi_id` | 是 | 唯一且与行为表一致 |
| `latitude` | 是 | POI 纬度 |
| `longitude` | 是 | POI 经度 |
| `category_l1` | 是 | 粗粒度类别 |
| `category_l2` | 是 | 细粒度类别 |

所有坐标必须使用同一种坐标系。公开实验建议统一转换为 WGS84。每个 L2 类别只能
属于一个 L1 类别。类别数量不固定，代码会根据数据中实际出现的类别自动编号。
